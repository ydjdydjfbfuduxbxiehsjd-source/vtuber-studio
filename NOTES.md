# VTuber Studio Pro - Отчёт о переписывании трекинга рук и плеч (v1.2.0)

## 1. Архитектурный контекст и почему переписан трекинг

### Проблема старой реализации (Positional Two-Bone IK)
Предыдущая система строилась на позиционном двухкостном IK (`solveArmVectorIK`):
1. **Зависимость от длины:** Позиционный IK вычисляет углы сгиба суставов из евклидова расстояния $d = \|P_{\text{wrist}} - P_{\text{shoulder}}\|$ по теореме косинусов:
   $$\cos(\alpha) = \frac{L_1^2 + d^2 - L_2^2}{2 L_1 d}$$
   При любом приближении ладони к лицу перспективное сокращение (ракурс вебкамеры) визуально искажало пропорции. Когда $d > L_1 + L_2$, аргумент косинуса выходил за пределы $[-1, 1]$ и принудительно зажимался в угол $0^\circ$, из-за чего рука аватара вытягивалась строго вбок в струну.
2. **Конфликтующие заплатки:** Наслоение масштабирования по плечам, калибровки Т-позы, множителей досягаемости (Reach multiplier), искусственного Face-Touch притягивания и коллайдеров приводило к постоянным конфликтам и нестабильности на разных моделях.

### Новое решение: Прямая кинематика по векторам направлений (Direction-Based FK)
Новый модуль `src/tracking/armRig.ts` полностью исключает позиционный IK:
- **Углы не зависят от длины костей:** Для каждой кости в иерархии (`upperArm -> lowerArm -> hand`) целевое направление вычисляется как нормализованный вектор:
  $$\vec{D}_{\text{upper}} = \frac{P_{\text{elbow}} - P_{\text{shoulder}}}{\|P_{\text{elbow}} - P_{\text{shoulder}}\|}, \quad \vec{D}_{\text{lower}} = \frac{P_{\text{wrist}} - P_{\text{elbow}}}{\|P_{\text{wrist}} - P_{\text{elbow}}\|}$$
- Направление переводится в локальную систему координат родительской кости через умножение на инвертированный мировой кватернион родителя ($Q_{\text{parent, world}}^{-1}$).
- Локальный поворот кости вычисляется через `Quaternion.setFromUnitVectors(restDirection, targetLocalDirection)`.
- Направления покоя (`restDirection`) вычисляются один раз при загрузке модели напрямую из нормализованных костей (`vrm.humanoid.getNormalizedBoneNode`).

## 2. Параметры и обоснование выбора

| Параметр | Значение | Обоснование |
|---|---|---|
| **1€ Filter minCutoff** | `1.0 Hz` | Фильтрация входных 3D world landmarks; устраняет мелкое дрожание суставов в покое. |
| **1€ Filter beta** | `0.03` | Нулевая задержка при быстрых взмахах и жестах (динамическое расширение полосы). |
| **Visibility threshold** | `0.5` | Суставы с видимостью ниже 0.5 игнорируются, используется последнее валидное положение. |
| **State Machine: HOLD** | `250 мс` | При кратковременном перекрытии ладони или выходе из кадра поза удерживается без рывков. |
| **State Machine: RELAX** | `400 мс` | Плавный экспоненциальный возврат в A-позу покоя при долгой потере трекинга. |
| **State Machine: Fade-in**| `150 мс` | Бесшовное включение трекинга при возврате руки в кадр без резкого щелчка. |
| **Elbow Bend Range** | `0° ... 150°` | Анатомический диапазон шарнира локтя: защита от выгибания назад и неестественного слома. |
| **Torso Elbow Repulsion**| `Радиус 0.14 м` | Мягкое выталкивание локтя из объема грудной клетки/торса без коллизий кисти. |
| **Twist Distribution** | `50% / 50%` | Скручивание предплечья делится поровну между lowerArm и hand (исключает эффект скрученной конфетной обёртки). |
| **Finger Joint Limits** | Proximal: $0\dots90^\circ$<br>Intermediate: $0\dots110^\circ$<br>Distal: $0\dots80^\circ$ | Полное соответствие физиологическим пределам сгибания человеческой кисти. |
| **Renderer Pixel Ratio** | `min(devicePixelRatio, 1.25)` | Предотвращает 4-кратную перегрузку GPU на мониторах высокой плотности, обеспечивая 60 FPS. |

## 3. Решение проблемы с производительностью (FPS 17-24 -> 60)

1. **Развязка рендеринга и трекинга:** Ранее `holisticInstance.send({ image: videoElement })` вызывался синхронно в коллбэке каждого кадра камеры, блокируя основной поток JavaScript на время работы нейросети (35–45 мс). Введён флаг `isHolisticBusy`: если инференс предыдущего кадра ещё идёт, камера не перегружает поток. За счёт этого цикл `requestAnimationFrame` (Three.js `animate()`) стабильно отрисовывает 60 FPS.
2. **Ограничение Pixel Ratio:** На экранах с масштабированием 125–200% рендерер раньше рисовал в разрешении до $5120 \times 2880$. Ограничение до `1.25` снизило нагрузку на шейдеры MToon в 2.5 раза.
3. **Zero-Allocation в цикле:** В новом модуле `src/tracking/armRig.ts` все вычисления направлений, кватернионов и матриц базиса ладони выполняются в переиспользуемых статических буферах. Сборщик мусора (GC) больше не вызывает просадок кадров.

## 5. Чек-лист для ручной проверки

Запустите студию двойным кликом по **`start.bat`** (или `npm start`) и откройте [http://localhost:5173](http://localhost:5173):

- [ ] **Базовая модель:** Убедитесь, что загружается `sample.vrm`, а кнопка `gyaru.vrm` удалена из интерфейса.
- [ ] **Версия в шапке:** Проверьте зелёный бейдж в верхнем баре: `v1.2.0 build 2026-10-23 23:00`.
- [ ] **Руки в стороны (Т-поза):** Разведите руки в стороны — руки аватара должны ровно разойтись параллельно плечам.
- [ ] **Руки вперёд:** Направьте руки к камере — руки аватара должны вытянуться вперёд (+Z) без ухода в стороны.
- [ ] **Руки вверх:** Поднимите руки вверх над головой (+Y).
- [ ] **Сгибание локтя:** Согните руку в локте и коснитесь плеча — локоть должен согнуться естественно, угол локтя отображается в HUD.
- [ ] **Касание лица (лоб, щека, нос):** Поднесите ладонь ко лбу, щеке или подбородку. Рука аватара теперь следует строго за направлением вашей руки и касается лица без выстреливания вбок.
- [ ] **Движения ладони и пальцев:**
  - Сожмите кулак — пальцы сгибаются во всех трёх суставах (MCP, PIP, DIP).
  - Покажите жест «Peace / V» — указательный и средний выпрямлены, безымянный и мизинец согнуты.
  - Покажите большой палец вверх — большой палец отводится в сторону и вверх.
- [ ] **Закрытие лица ладонью:** Закройте лицо ладонью. При потере детектора кисти плечо и локоть продолжают точно следовать за движениями руки по позе, кисть сохраняет устойчивость.
- [ ] **Уход руки из кадра:** Быстро опустите руку вниз или уберите из кадра — рука плавно переходит в `HOLD` -> `RELAX` -> `REST` и опускается вдоль тела в позу покоя (без рывков). При возвращении в кадр — плавный fade-in за 150 мс.
- [ ] **Отладка (клавиша `D`):** Нажмите `D` на клавиатуре. На экране появятся:
  - Полупрозрачный 3D-скелет (бирюзовый для левой руки, розовый для правой) прямо поверх аватара;
  - HUD с текущим состоянием машины состояний (`ACTIVE`/`HOLD`/`RELAX`/`REST`), углами локтей и FPS.
